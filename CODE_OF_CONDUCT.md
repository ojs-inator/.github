# Code of conduct

Be respectful, technically honest, and safe for contributors and operators.

- Focus review on behavior, evidence, risk, and architecture—not the person.
- State uncertainty, failed validation, and operational risk plainly.
- Preserve other contributors' work and credit its provenance.
- Protect credentials, customer data, infrastructure details, and production state.
- Prefer explicit handoffs and reversible changes when work overlaps.

Technical disagreements should be resolved through issues or ADRs. Maintainers should handle conduct concerns privately and proportionately. See the canonical [`kmanweb-roadmap` code of conduct](https://github.com/ojs-inator/kmanweb-roadmap/blob/main/CODE_OF_CONDUCT.md) for the full shared policy; repository-local policies may add stronger requirements.
